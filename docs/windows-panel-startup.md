# Windows 主题面板与默认启动

本功能将背景选择、启动设置和操作日志接入原生 WinForms 面板。面板与默认启动图标使用相同的活动主题配置；快捷方式不固定某一张图片。

## 使用

1. 打开 **DreamSkin 主题管理**，在“主题与启动”页选择主题及背景图片。列表或文件选择只创建草稿，尚不改变已保存设置。
2. 点击 **保存为启动设置**，保存完整主题及受管图片副本。该操作不启动 Codex；如果皮肤已经运行，保存可能同步更新当前外观。
3. 点击 **应用 / 重新应用并启动 Codex**，按需要处理重启确认。只有启动与渲染验证通过，面板才报告已应用；取消不会提交草稿。
4. 点击 **创建 / 修复默认启动快捷方式**，生成桌面上的 **Codex · 默认主题启动**。下次直接双击该图标即可使用保存的主题与背景。

Setup 安装同时在安装目录生成 **Codex · 默认主题启动.lnk**，可直接使用，也可复制到本机桌面；桌面图标被删除后也能通过面板重新创建。快捷方式指向当前用户的受管引擎，不依赖快捷方式所在目录。每台电脑安装时生成自己的路径，不将开发者电脑的 `.lnk` 作为通用源码文件分发。

透明度区明确标注“当前活动主题”，沿用即时保存行为；它修改当前主题的本机透明度覆盖，不是尚未提交的草稿。已保存主题库不会因替换活动背景而被覆盖。PNG/JPEG 可以预览；系统未安装 WebP 解码支持时显示说明，保存时仍走完整图片校验。

## 失败、恢复与重复请求

保存使用校验完整草稿后交换活动目录的事务；应用使用现有启动选择快照与验证流程。失败信息分别显示“配置恢复”和“可见外观恢复”；可见外观没有通过验证时，不宣称已经恢复，并保留相关恢复备份。

保存前写入持久事务记录。若进程中断，下次保存、启动或安装会在初始化前尝试恢复完整旧配置；发现外部的新修改时停止恢复并保留证据。不会因活动目录暂时缺失就重新生成默认主题。

应用期间禁用重复提交，跨入口通过操作锁避免重叠事务。重新应用操作保留；不会仅凭主题名称相同就跳过渲染验证。正常页面导航的重新注入继续由现有 watcher 处理。

## 日志

“日志”页支持查看、筛选、展开详情、复制脱敏记录及导出诊断。快捷方式、面板与托盘操作均可记录；无需保持面板打开。底层 injector 和 verify 日志也可从该页打开。

“打开日志目录”指向 `%LOCALAPPDATA%\CodexDreamSkin\logs`。结构化操作日志最多保留五个约 5 MiB 文件；面板读取最近的有界尾部。日志故障不改变已经验证的应用结果。用户取消与缺少验证结果是不同状态。

## 本机构建与更新

- 面板需要 .NET SDK 8 或以上：在仓库根执行 `node tools/build-theme-manager.mjs`。PowerShell 脚本无需编译。
- 源码安装仍使用 `windows/scripts/install-dream-skin.ps1`，需先退出托盘和 Codex。
- 已有 Setup 安装目录可运行 `tools/prepare-windows-update.ps1 -InstallRoot <安装目录>` 准备本地构建，保留原 payload 备份。此步骤不关闭 Codex，也不替换运行引擎。
- 准备后，退出 Codex，双击安装目录中的 `Update DreamSkin Panel`。维护入口复用正常安装身份、维护锁、备份与更新流程；更新完成打开新面板。
- 日常再使用管理入口或默认启动图标，不必反复运行维护入口。完整对外分发仍需构建 Setup，纳入相同脚本和面板产物。

本地更新保持版本号不变，不表示已发布新 Release。运行引擎未激活前，旧面板仍代表旧版本；构建成功、payload 准备完成和真实 Codex 验证需要分别记录。
